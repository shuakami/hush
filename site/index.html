Credentials,
brokered.

Hush is a credential broker. It stores secrets in an encrypted vault and runs commands on remote hosts on the caller's behalf — so Python scripts, CI jobs, and AI agents never handle a raw password or key themselves.

how it works

One HTTP API.
Four resolved layers.

Callers talk to a single broker. The exec engine resolves a named host through the inventory, fetches the credential from the vault, dispatches through the matching transport, and appends the result to the audit chain. Each layer is testable in isolation and wears a single responsibility.

vault

Encrypted at rest. Streamed at use.

AES-256-GCM with envelope encryption. Each secret has its own DEK, wrapped by a KEK sourced from env, file, or KMS. Plaintext lives in memory only between the vault read and the transport handshake.

inventory

Names, not addresses.

hk1 is a name. Behind it: password SSH, key SSH, jump-host chain, or a curl-based relay tunnel — same call site. Tagged hosts make hush exec --tag prod -- uptime a one-liner.

audit

Hash-chained. Verifiable.

Every read, exec, put, and get is appended to a hash-chained log. hush audit verify walks the chain and refuses to validate if any record has been mutated. Same primitive Sigstore Rekor uses for supply-chain proofs.

api

Scoped tokens. Streaming responses.

Bearer tokens are scoped per resource (secret:read, host:exec, …). Output is streamed, not buffered — large jobs don't bloat the broker's memory.

audit

Every call leaves a verifiable trace.

Hush records the actor, the action, the resolved target, and the outcome — then commits the SHA-256 of the previous record into the next. Tampering breaks the chain. Operators trust agents because the agents leave a complete trail.

getting started

          
Five minutes, end to end.

        


        
    
          
  1. 
            
    01
    
            
    
              
    Pick a master key
    
              
    Hush encrypts the vault with a key-encryption-key (KEK) that never lives in the database.
    

    $ export HUSH_MASTER_KEY=$(openssl rand -base64 32)
    
            
    
          
    2. 
          
  2. 
            
    02
    
            
    
              
    Start the broker
    
              
    One process, one port. Daemonise with systemd, docker, or tmux — your call.
    

    $ hush bootstrap        # mints admin token (printed once)
$ hush server           # listens on 127.0.0.1:8443
    
            
    
          
    3. 
          
  3. 
            
    03
    
            
    
              
    Log the CLI in
    
              
    Writes ~/.hush/config at mode 0600. Every later command reads it automatically.
    

    $ hush login --endpoint http://127.0.0.1:8443 --api-key hk_live_…
    
            
    
          
    4. 
          
  4. 
            
    04
    
            
    
              
    Register a host
    
              
    Push the credential into the vault, then attach it to a name in the inventory.
    

    $ echo 'super-secret-root-password' | hush secret set hk1-root-password --stdin
$ hush host add hk1 \
    --transport ssh --address 10.0.0.10 --port 22 --user root \
    --auth-kind password --auth-secret hk1-root-password --tag prod
    
            
    
          
    5. 
          
  5. 
            
    05
    
            
    
              
    Use it
    
              
    The entire daily-driver loop.
    

    $ hush exec hk1 -- "systemctl status nginx"
$ hush exec --tag prod -- "uptime"
$ hush cp ./build.tar.gz hk1:/opt/app/build.tar.gz
$ hush ssh hk1
$ hush audit verify

for AI agents

          
A skill, a CLI, a scoped token.

          
Modern coding agents speak bash; Hush is shaped for that. The repo also ships an Agent Skill for runtimes that load skill directories — Claude Code, Claude Desktop, Cursor, Aider, Devin via AGENTS.md.

        


        

          

            
01Install the skill


$ mkdir -p .claude/skills
$ cp -r skills/hush .claude/skills/hush

            
The skill describes when to call Hush, the verbs, common patterns, and the boundaries — for example, never echoing the plaintext of a vault entry.

          


          

            
02Mint a scoped token


$ hush apikey mint \
    --name claude-code \
    --scope host:exec,host:list,secret:read

            
API keys are scoped: secret:read, host:exec, host:put, audit:read, … Mint one per agent, revoke when done.

          


          

            
03Watch the trail


$ hush audit tail --follow
host.exec    hk1   exit=0   "systemctl status nginx"
secret.read  hk1-root-password   caller=claude-code

            
Every read, exec, put, and get is appended to the chain. Operators trust agents because the agents leave a complete trail.
